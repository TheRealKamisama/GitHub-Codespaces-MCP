# M0 开发 PoC / Development PoC

当前为未发布源码实现，内部软件版本来自 `package.json`。这不是可安装预览版，也不代表完整 M0 云端验收通过。

## 已实现范围

官方 MCP SDK 的 stdio 初始化、版本协商、tools/list 和 tools/call；五个稳定英文工具有严格输入 schema、输出 schema、structuredContent 与相同 JSON 文本。仅声明 tools capability。错误消息支持 en/zh-CN，按显式 locale → 已有绑定 locale → en 选择。自然语言仍由宿主理解；没有 Prompts 模板。

| 工具 | 当前行为 |
|---|---|
| `environment_check` | gh 版本、结构化认证状态、只读 `/user` 实际身份核验；可核对 expectedAccount；不返回凭据或原始错误输出 |
| `codespace_list` | 每页最多 30 个已有实例；显式 page/nextPage；不启动实例 |
| `project_bind` | 核对账号、仓库、实例 owner；保存本机绑定，expectedVersion 防覆盖；仅 shared/reuse_only |
| `codespace_prepare` | 先持久化 operation，再核对 Available，安装固定摘要 runner 并握手；同 requestId 恢复同 operationId；每次重新探测，不缓存就绪结论 |
| `runner_probe` | start/status 固定十秒后台诊断；同 requestId 查询同记录；不执行任意用户命令 |

prepare 返回的是操作记录。必须检查 `data.state`：`ready` 仅表示本次 M0 传输探测通过，`failed`/`unknown` 不是成功就绪。`errorCode` 给出原因；传输超时只改变观测，不能推断远端执行失败。继续用原 requestId 调用以对账，不换 ID 重放。

**M0 本身没有实现**（其中 project_inspect、精确 SHA 与 job/日志已由 [M1 首个切片](M1.md) 补充）：project_inspect、本地项目根目录识别、源码 fetch/精确 SHA 验证、通用 job、日志/产物接口、自动回收控制进程、实例启动/创建/停止/删除、服务、Docker、输入上传及端口转发。未注册的工具不能调用；start_existing/create_if_missing 在输入校验时拒绝。完整产品仍须完成 M1 的自动导出与资源释放闭环。

## 从源码运行

前置条件：Node.js 22+、npm、Git；调用 GitHub 工具时还需 gh 和用户已有登录。构建读取本仓库 Git HEAD，源码快照不能缺少 Git 元数据。开发依赖随 lockfile 固定；SDK/Zod 是运行时依赖，TypeScript 和 Node 类型仅用于开发。SDK、Zod、Node 类型使用 MIT，TypeScript 使用 Apache-2.0；没有额外安装或登录脚本。

```sh
npm ci
npm run typecheck
npm run build
node dist/cli.js serve --stdio
```

最后一条启动后等待 MCP 客户端消息，不显示 banner，也不连接云端。宿主使用 Node 可执行文件和上述三个参数（dist/cli.js 应使用真实绝对路径）；不要通过 npm start 承载宿主 stdio，因为 npm 会向 stdout 打印脚本标题。没有全局包安装或 npm 发布。

本机状态默认在 Windows `%LOCALAPPDATA%/github-codespace-mcp`；其他平台为 `~/.local/state/github-codespace-mcp`。可用进程环境 `CODESPACE_MCP_STATE_DIR` 指定绝对开发目录。状态保存绑定与 prepare 记录，不保存 token；将其放在当前用户控制的目录，不在不可信仓库中共享。

## 绑定与最小真实验证（当前 NOT RUN）

先在宿主用 `environment_check` 和 `codespace_list` 核对已有账号与实例。由用户选定目标和空目录，取得在该运行中实例安装诊断文件、运行十秒诊断的授权后，再调用：

```json
{
  "projectId": "dev/sample",
  "expectedAccount": "YOUR_ACCOUNT",
  "repository": "OWNER/REPO",
  "codespaceName": "YOUR_EXISTING_RUNNING_CODESPACE",
  "remoteProjectRoot": "/workspaces/mcp-poc-sample",
  "githubHost": "github.com",
  "ownership": "shared",
  "preparePolicy": "reuse_only",
  "expectedVersion": 0,
  "locale": "zh-CN"
}
```

这是占位示例；实际调用替换为已选定实例。绑定不连接 SSH、不创建目录或实例。M0 按 projectId 直接选择本机绑定，不读取仓库任务配置。更新绑定必须提供返回的旧 version；修改执行绑定后不能用旧 prepare requestId 执行不同计划。

1. 调用 `codespace_prepare`：`{"projectId":"dev/sample","requestId":"prepare-1","policy":"reuse_only"}`。保留返回 operationId；只有 ready 和握手身份/摘要都一致才是传输通过。
2. 调用 `runner_probe`：`{"projectId":"dev/sample","requestId":"probe-1","action":"start"}`。它只持久化状态并启动固定十秒诊断，不运行仓库代码。
3. 关闭本地 MCP（每次 SSH 调用本来就会退出），重启后以同 projectId/requestId 调用 action=status。应看到同 probeId、startedAt 和最终 completed。重复 start 不重新执行。强制切断传输、响应丢失及实例重启另做有界验收，不由普通重连推断通过。
4. 检查未生成第二个 probe；检查远端身份、generation、runnerSha256、version/gitSha/dirty。若 generation 改变，旧非终态为 interrupted；心跳过期但缺少重启证据为 unknown，不能猜测完成，也不自动重跑。
5. 本轮只使用 shared 已运行实例；M0 不自动停止或删除它。诊断十秒结束，文件保留在明确的目标目录。云端清理和后续停止由已有使用者的授权策略处理，不能宣称自动释放已通过。

`gh codespace ssh` 可能创建本地 SSH 身份文件；这是 gh 的行为。Available 检查和 SSH 连接之间仍存在状态变化竞态，M0 不承诺云端的原子 reuse-only 保证；真实验证时应使用状态稳定且已授权使用的实例。没有 devcontainer post-create 生命周期就绪验证，ready 不等于可执行任意项目任务。

## 传输与持久化边界

- 本地 argv 使用 shell=false，UTF-8 在完整字节拼接后解码。单子进程期限 12 秒、stdout+stderr 总上限 256 KiB；超时尝试结束本地进程树，权限不足返回 PROCESS_CLEANUP_UNCONFIRMED，不无限等待管道。
- SSH 命令只有固定 Python 入口。用户路径、绑定和源文件通过 stdin JSON 传输，不进入 shell 字符串；不使用 gh cp --expand。
- runner 安装在空项目根目录下的 `.codespace-mcp/runner/<build-digest>/`。只接受 `/workspaces` 子目录，拒绝现有用户内容、符号链接、归属冲突和摘要不一致。内容摘要证明随包内容一致，不单独证明发行来源。
- Python 标准库 runner 仅支持 Linux，探测 Python、Git、Codespace 名称与 generation；不检查 Docker。诊断用独立会话、关闭继承管道并移除 GitHub token 环境变量。它不是恶意同用户代码的安全隔离边界。
- 本地状态在同目录写临时文件并 rename；所有修改使用跨进程目录锁。远端使用 flock 和原子替换。进程崩溃后的锁不自动抢占：确认所有本 MCP 进程已停止后，才可删除状态目录中的空 `mutation.lock` 目录。不可删除整个状态目录来“修复”重复请求。
- 安装中断可以对同一摘要重试；owner 标识缺失/损坏时失败关闭，不自动接管。诊断接受记录先于 spawn；接受后崩溃可成为 unknown，禁止用重试自动重复执行。
- 准备操作只在当前调用中推进，没有后台 prepare 控制器。一次调用包含多个有界 gh 命令；宿主如设置工具期限，应留出至少 90 秒。中途断开后复用原请求恢复。

## 检查与证据（2026-10-13）

常见故障处理：GH_NOT_FOUND 需修正宿主 PATH；AUTH_REQUIRED 在本机核查 gh 登录；AUTH_IDENTITY_MISMATCH / REPOSITORY_MISMATCH 需核对绑定而不是切换账号重试。CODESPACE_NOT_READY 必须等待已有实例就绪，本服务不自动启动。WORKSPACE_CONFLICT / PATH_INVALID 需选择空的、非符号链接目录，不能清空用户文件来绕过。HASH_MISMATCH / RUNNER_INCOMPATIBLE 需检查可信源码构建与远端安装，不能忽略摘要。STATE_INVALID 需保留损坏状态调查；STATE_BUSY 的锁恢复规则见上文。unknown / PROCESS_CLEANUP_UNCONFIRMED 要用同 requestId 对账并确认本地相关进程，不能声称远端已结束。

## English

This is an unreleased source-only M0 transport PoC. Run `npm ci`, `npm run build`, then connect an MCP client directly to Node with `dist/cli.js serve --stdio`. Do not use npm as the stdio transport launcher. Startup makes no cloud calls. Only the five tools listed above exist; schemas are strict and outputs include matching structuredContent and JSON text.

Only explicitly bound, existing, Available shared Codespaces are supported. Prepare installs and verifies the bundled Python probe; ready is transport readiness, not project task readiness. The fixed ten-second diagnostic tests persistence and reconnection using the same requestId. No general jobs, exact-commit execution, artifact export, automatic resource release, create/start/stop/delete, Docker or public package are implemented. The full product still requires these later milestones.

Windows build, 14 Node tests, five portable Python tests and a read-only live GitHub identity check passed. On 2026-10-14 the same Node checks passed on a Linux client, and the Linux runner integration test passed inside a podman container with a writable `/workspaces` (not a real Codespace). GitHub/runner fault paths use simulations. Real Codespaces SSH survival/restart remain NOT RUN. No cloud resource was created, started or modified. The local process-tree tests required execution outside the restricted sandbox; permission failures now return a bounded cleanup-unconfirmed error. Run the Linux integration test and the explicitly authorized live sequence above before claiming cloud readiness. Shared instance billing and cleanup remain with its existing owner; this PoC does not automatically stop it.
